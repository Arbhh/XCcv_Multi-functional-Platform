# 显卡掉频排查指引（XCcv 工控机版）

> 适用症状：**同一模型、同一批图，推理耗时忽快忽慢**（如单图 300ms 突然
> 变 1s+），或批量测试中出现"疑似 GPU 掉频/热节流"告警。
> 本文档为按 XCcv 实际能力整理的排查清单。

## 一、先看现象：XCcv 平台内的两个观测点

1. **测试平台 → 批量运行**：摘要给出 单图耗时 min/p50/avg/max。若出现
   "疑似 GPU 掉频/热节流"告警（单图耗时 > 中位数×3），按本文排查。
2. **部署平台 → 推理服务（服务运行中）**：页面顶部 GPU 状态条每 10 秒
   刷新：性能状态（P-state）/温度/功耗/利用率/SM 频率。
   **P0~P5 正常；P6/P8/P10/P12 = 掉频状态**（会直接标注 ⚠）。

也可手动执行（cmd）：

```
nvidia-smi --query-gpu=timestamp,pstate,temperature.gpu,power.draw,utilization.gpu,clocks.sm --format=csv -l 1
```

观察掉频时刻是否与推理耗时上升同时出现。

## 二、最常见原因与处置（按命中率排序）

| # | 原因 | 判断 | 处置 |
|---|---|---|---|
| 1 | **Windows 电源计划/节能** | P-state 反复跳 P8；功耗远低于额定 | 控制面板→电源选项→选「高性能」；设置→系统→电源→"电源模式"调最佳性能 |
| 2 | **EcoQoS / 进程被降频调度** | 同机器偶发慢 2~3 倍、与负载无关 | XCcv 已在进程入口强制 HighQoS（win_qos，自动处理，无需操作）；若自行写脚本调服务，注意别在后台低优先级启动 |
| 3 | **显卡驱动设置** | 长期低频 | NVIDIA 控制面板→管理 3D 设置→电源管理=「最高性能优先」；关闭"Optimal power / Adaptive" |
| 4 | **多显卡（核显/独显混跑）** | 推理根本没进 N 卡 | 设备管理器确认推理进程跑在独显；Windows 图形设置→该应用→高性能 GPU |
| 5 | **热节流** | 温度 >85℃、频率随温度下降 | 清灰/换硅脂/加风道；工控机柜通风；夏季机房温度 |
| 6 | **供电不足** | 负载高时频率骤降 + 功耗封顶 | 检查电源额定功率、外接供电线是否插满 |
| 7 | **加密校验/安全软件周期扫描** | 周期性（如每几分钟）尖刺 | 杀软把 XCcv 安装目录与 python 加入排除；企业终端安全软件排查 |

## 三、XCcv 特定说明

- **TensorRT 引擎与显卡绑定**：换显卡或驱动大版本变化后，旧 `.engine` 引擎
  无法加载——这是机制限制不是掉频，重新导出即可。
- **首次推理慢**：服务端在加载后预热；测试平台批量前自动预热一张——
  预热后仍慢才是掉频信号。
- **CPU 瓶颈与 GPU 掉频的区分**：JPEG 解码等 CPU 环节占主导时
  （4K 图解码通常在百毫秒量级），耗时波动更像 CPU 调度问题；
  GPU 状态条不掉频则查 CPU/磁盘。
- **P-state 判读**：P0 满频 → P6/P8 空闲降频。推理时刻应观察到 P0~P2；
  推理中仍 P6+ = 系统在压频率，按上表 1/3/4 排查。

## 四、仍无法解决时

收集以下信息反馈：GPU 状态条截图（运行中）、`nvidia-smi -q -d PERFORMANCE`
输出、驱动版本（`nvidia-smi` 首行）、平台日志
`platform_data/logs/<平台>.log` 中的批量耗时行。
